# 第四阶段 · 产品级重构计划

> 日期：2026-11-19  
> 输入：`docs/redesign/product-design-v2.md`、`docs/redesign/visual-directions.md`、`DESIGN.md`  
> 视觉方向：B + A + C（读本骨架 + 案卷事实 + 行动路线）  
> 状态：实施计划，尚未修改正式业务代码  
> 原则：先做结构，再做视觉；先保任务，再做表达；每个里程碑都可单独验收。

## 1. 目标

把当前“能跑通”的原型，重构为一条**手机可完成、结论先行、事实单一来源、边界清楚**的案件工作台：

- 首页：让工友在 3 秒内知道“这里能帮我整理欠薪”，并在首屏开始。
- 对话：一次一个问题，助手回答短、事实可核对、确认后有明确的下一步。
- 分析：先给三条结论，再给证据缺口、权益和渠道；不再是一张长资料表。
- 行动：三阶段 / 八步骤，当前步骤默认展开，路线只表达“现在在哪”。
- 填报：移动端可完整走完七步，证据目录改卡片，文案明确“本人提交”。
- 视觉：B 的工人读本为主，A 的案卷事实页签与核对章，C 的行动路线。

### 非目标

- 不新增跨地区、跨行业、OCR、上传证件、自动提交、账号登录。
- 不重写 Agent v1 的模型循环、边界和工具；只接它的真实输出。
- 不把离线 HTML 嵌入正式前端，不保留第二套 mock 数据。
- 不在本阶段做大规模动画、主题切换或深色模式。

## 2. 开工前检查

1. **分支**：从当前工作树确认基线，创建独立重构分支；不要直接在已有未提交改动上重置或覆盖。
2. **保护现有工作**：`git status` 中已有未提交修改，先确认归属；不执行 `reset --hard`、`checkout --`、`clean -f`。
3. **基线**：记录当前 `npm run test`、后端测试、`npm run build` 结果；保留 `docs/redesign/evidence/` 旧截图作为 before。
4. **环境**：3000 前端 / 8000 后端；不要在前端 dev server 运行时执行 `next build`，避免 `.next` 冲突。
5. **验收尺寸**：1440 × 900 与 390 × 844；390 是第一验收尺寸。

| `surface` | `#fffdf8` | 阅读面、事实档案、底部导航 |
| `sand` | `#eae1d0` | 分区、页签、非活动面 |
| `ink` | `#171717` | 主文字、按钮、标题 |
| `muted` | `#5d574d` | 次级文字、元信息 |
| `rule` | `#d9ccb4` | 发丝线、输入边、卡片边 |

- 字体：单一系统无衬线栈；标题 800，正文 400/1.75；移动端正文 16px。

## 5. 数据与状态（W8）

### 5.1 双进度

- 案件头：`信息完整度` 使用 `case.progress`；`办理进度` 使用 `case.step_progress`。
- 分析页只显示信息完整度；行动页只显示办理进度；两者不混用。

### 5.2 结果过期

现有字段不足以稳定判断“分析是否基于最新事实”：

- `case.updated_at` 会因聊天消息变化，不能直接当事实版本。
- 推荐后端增加 `facts_revision`（整数）或 `facts_updated_at`；派生的 analysis/action/form 返回生成时的版本。
- 前端比较版本；不一致时显示统一“信息已更新，请重新生成”。
- 最低限度：在当前会话中由 `case-provider` 维护 dirty 标记；但刷新后必须仍能判断，否则不满足验收。

### 5.3 结论与阶段

- 分析结论可从现有 `rights`、`evidence`、`jurisdiction` 派生，不新增模型调用。
- 行动阶段按稳定 `step_key` 前端映射；若后端阶段字段更合适，再单独提案，不在本次重构中混入。

- [ ] 复制字段、复制陈述、DOCX/PDF 导出可用。
- [ ] 模型/后端失败时可降级继续，输入不丢。

### 视觉

- [ ] B 的读本体量：新闻纸、粗黑标题、16px 正文、红色只标记当前/风险。
- [ ] A 的事实档案：页签 + 已核对章 + 唯一的 320px 事实面板（移动端摘要条）。
- [ ] C 的路线只在行动页/下一步黑块出现，分析页没有路线装饰。
- [ ] 无宋体标题、无大圆角卡片、无阴影、无渐变、无玻璃拟态。
- [ ] 390px 与 1440px 截图均通过；无控制台错误。

### 法律与隐私

- [ ] 不收集身份证号/银行卡/证件照；不新增上传。
- [ ] 官方入口写“本人提交”；不出现“自动提交/代为投诉”。

- [ ] 复杂/紧急情况保留 12348/12333 兜底。

## 9. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| B 的红色被用成装饰 | 读本变成警报页 | 执行 Red Pencil Rule；每屏一个红色主焦点 |
| A 的案卷感变成旧公文 | 页面变旧、变密 | 只保留页签/核对章；不用宋体/纹理/印章图形 |
| C 的路线语言扩散到分析页 | 认知负担增加 | 路线只出现在行动步骤和下一步黑块 |
| 390px 字号提升导致页面更长 | 滚动增加 | 结论先行 + 折叠依据；不删事实，删重复 |
| 事实过期没有稳定版本 | 用户拿旧结果办事 | 增加 `facts_revision` 或等价字段；不接受仅本地 dirty |
| 现有未提交改动被覆盖 | 丢工作 | 开工前确认归属，独立分支，禁止破坏性 git 命令 |
| 行动阶段映射依赖 step_key | 后端改名导致错位 | 映射集中在一个文件并加测试；缺失时回退为顺序列表 |

本计划不包含代码实现；下一步是按里程碑开工，并在每个提交后更新验收证据。
