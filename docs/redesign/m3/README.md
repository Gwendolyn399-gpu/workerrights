# M3 · 对话页与事实档案面板

> 日期：2026-11-19  
> 分支：`feat/visual-refactor-m1`  
> 状态：已完成  
> 依据：`DESIGN.md`、`docs/redesign/refactor-plan-v2.md`、`docs/redesign/product-design-v2.md`

## 1. 本轮范围

把对话页与事实面板迁移到 B + A 的视觉结构：

- 对话气泡、流式回复、输入区、语音入口、快捷回复。
- 信息确认区：`已整理 x/11 项`、`请核对案件档案`、`确认信息，生成分析`。
- 确认后下一步入口：`下一步：看案件分析`、`直接看行动步骤`。
- 事实面板：`事实 / 法律依据`两个页签、`已核对 / 待核对`章、未知值灰色。
- 移动端案件档案摘要条 + 底部面板。
- 发送失败时保留输入并提供重试。
- 法律依据弹窗同步迁移到纸面体系。

本轮**没有**改后端接口、Agent 规则、法律内容，也**没有**迁移分析、行动、填报页面。

## 2. 对话页

| 区域 | 变化 |
| --- | --- |
| 助手消息 | 增加轻量“助手”标识；纸白/沙色表面、发丝边；引用收进“查看依据” |
| 用户消息 | 墨黑整块、纸白字；2px 方角 |
| 流式回复 | 与正式消息一致的气泡；“正在看你的消息…”等状态保留 |
| 快捷回复 | 2px 方角、44px 触控高度；多选保持原有逻辑；开放问题不生成假按钮 |
| 确认区 | 只在本轮确实进入确认关口时出现；点击发送“信息无误，生成分析”，不自动确认 |
| 输入区 | 聊天输入框 48px；发送 48px；语音按钮 44px；移动端输入区保持在底部导航上方 |
| 模式标识 | 本地规则模式明确显示“本地规则整理 · 不是在线大模型” |
| 失败 | 错误就地显示，输入恢复，提供“重试”；不重复自动发送 |
| 移动端 | 对话区固定高度、消息内部滚动；顶部档案摘要条可打开底部档案面板 |

## 3. 案件档案

- 顶部 3px 墨黑案卷头，标题“案件档案”。
- `事实 / 法律依据`页签；当前页签深红文字 + 2px 红线。
- 右对齐核对章：已确认显示绿色实线“已核对”，未确认显示琥珀虚线“待核对”。
- 事实行保持唯一事实源；未知值显示“待核实”，使用墨灰而不是红色。
- 欠薪金额是唯一红色强调；其他值使用墨黑。
- 未整理项用琥珀提示条列出；不确定项单独说明。
- `法律依据`页签按需请求现有 `/legal-basis` 接口，显示前 3 条、来源与核验状态；完整列表仍进入原弹窗。
- 法律状态使用短标签：`已核验 / 待逐条核验 / 待核验`，完整说明保留在详情中。
- 桌面面板吸顶并限制高度，内容过长时面板内部滚动。
- 移动端不显示 320px 面板，改为摘要条 + 底部面板。

## 4. 验收路径

已用浏览器实际走通：

1. 新案件 → 首页“说说我的情况”。
2. 点击“郑州”快捷回复 → 助手追问区县，档案更新为“河南 · 郑州市”，信息完整度变为 1/11。
3. 补全事实后进入确认关口 → 确认区出现 `11/11`。
4. 打开案件档案 → 核对事实、切换到法律依据。
5. 点击“确认信息，生成分析” → 助手确认，出现“下一步：看案件分析”。
6. 刷新后事实、确认状态与核对章保留。
