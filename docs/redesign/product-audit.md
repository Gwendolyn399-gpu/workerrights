## 2. 参考项目带来的方法结论

参考项目最有价值的不是黄色视觉，而是交付纪律：

1. **一句话定义产品，明确 In / Out of scope。** 参赛作品最怕“什么都能做”，最后没有一条能走通。
2. **每个任务有可验证的验收标准。** 从“页面存在”改成“用户在真实浏览器里完成了什么”。
3. **用证据说话。** 截图、网络请求、构建结果、测试结果，以及明确的 PASS / UNVERIFIED。
4. **移动端优先验收。** 目标用户在手机上，桌面截图不能替代 390px 的核心流程。

不照搬：黄色/黑色强视觉、宠物示例、营销式统计条。它们服务于另一个产品和受众。

## 3. 离线 HTML 的评估

### 3.1 值得吸收的部分

- **气质**：纸白、沙色、陶土色、衬线标题带来的“案卷 / 办事材料”感，比纯系统无衬线更接近本产品。它能降低“冷冰冰的政务工具”感，同时保持克制。
- **信息节奏**：首页先说明“慢慢说，我们一起理清”，再给四步路径、范围与隐私边界，用户知道自己在进入什么流程。
- **案件壳层**：面包屑、案件标题、示例标记、顶部/底部导航、虚构提示条的组织方式清楚。
- **事实档案**：右侧“案件档案”把地点、工种、时间、工资、欠薪、合同、招用管理、已有材料集中展示，符合“先核对再生成”的心智。
- **分析结构**：基本情况 → 用工关系 → 证据与缺口 → 可能权益 → 法规参考 → 风险与管辖，顺序合理。
- **行动结构**：优先渠道 + 正式陈述 + 分步清单 + 时效与风险 + 渠道汇总，内容完整。
- **填报结构**：左侧步骤、右侧逐字段说明、底部正式陈述与证据目录，任务边界清楚。
- **文案边界**：不代替提交、12348/12333 兜底、虚构示例提示，均明确。

### 3.2 不能直接搬进正式前端的原因

- 它是单文件静态原型：`DATA` 是写死的 mock，路由是 hash，操作是本地状态，没有真实 API、SSE、会话隔离、错误状态和后端持久化。
- 部分交互是“看起来能做”：按钮只切换本地视图，不能创建案件、保存事实或导出真实材料。
- 依赖 CDN 与单文件内联逻辑，和 Next.js 正式前端的组件、类型、接口体系重复。
- 它没有真实失败路径：模型不可用、网络失败、事实冲突、导出失败都未覆盖。

### 3.3 融合原则

**吸收视觉语言、内容层级和交互模式；不嵌入 iframe，不复制 mock 数据，不保留第二套业务逻辑。**

正式前端应继续是唯一实现：用真实 `caseData`、Agent SSE、分析/行动/填报 API 驱动页面；离线 HTML 只作为设计参照和内容清单。

## 4. 当前产品逐面审计

### 4.1 首页

**做得好**

- H1 直接说“被拖欠工资？说说你的情况”，用户 3 秒内知道来对了地方。
- 主按钮与演示入口清楚，范围、隐私、不代替提交的边界都在首屏或首屏下方出现。
- 页面短、加载快、无横向溢出。

**问题**

| 级别 | 问题 | 证据 / 影响 |
| --- | --- | --- |
| P2 | 当前首页过于“空白说明页”，没有传达“这是一条可以走完的路” | 只有四步列表，没有案件成果预览、分析/行动/材料会产出什么；与离线版相比信任感弱 |
| P2 | 首屏没有把“匿名、无身份证、不自动提交”三项关键信任信号聚合成一组 | 边界文案在底部，首屏只靠按钮建立信任 |
| P2 | 视觉身份偏通用后台 | 纸白 + 蓝按钮可以属于任何工具；离线版的案卷气质没有进入正式前端 |

**方向**：保留直接的 H1 和主 CTA，吸收离线版的四步叙事、范围说明和一组克制的信任事实；不回到营销长页。

### 4.2 我的案件

**做得好**

- 匿名会话解释清楚，删除不可恢复的警告明确。
- 空状态有下一步入口。

**问题**

| 级别 | 问题 | 证据 / 影响 |
| --- | --- | --- |
| P1 | 同一页面出现三组“开始/演示”入口 | 顶部按钮、空状态按钮、页脚说明并列，主次不清 |
| P2 | 案件行缺少“下一步做什么” | 只有进度和“继续”，用户不知道回去该看分析、做步骤还是补材料 |
| P2 | 空状态信息密度低 | 大块留白，没有展示“一个案件整理完会得到什么” |

### 4.3 对话

**做得好**

- 一次一问的交互成立，快速回复、事实修改、法律依据、语音入口都在。
- SSE 草稿、停止、错误提示、确认后的下一步入口都有承接。
- 事实侧栏与对话同屏，符合“边说边核对”。

**问题**

| 级别 | 问题 | 证据 / 影响 |
| --- | --- | --- |
| P1 | 助手回复偏长，且没有显眼的助手身份 | 当前示例中一条回复可占 4–6 行；用户需要读完才知道要回答什么 |
| P1 | 事实修改后没有全局“分析已过期”提示 | 用户可能拿旧分析去做下一步；当前页面没有统一 stale 状态 |
| P2 | 对话首屏从历史中段开始 | 自动滚到底部，用户看不到开头；没有“回到开头/最新”的定位 |
| P2 | 移动端输入区在页面内，不是稳定的底部工作区 | 软键盘弹出时可能被顶走；本轮未在真机验证 |
| P2 | 页脚服务商文本与底部 tab 距离过近 | 移动截图中内容贴近固定导航，需要统一安全区留白 |

**方向**：把“当前问题”做成对话的视觉焦点；回复先给结论/追问，再给解释；引用折叠；确认后明确给出“下一步：看分析”。

### 4.4 案件分析

**做得好**

- 信息完整度、基本情况、用工关系、证据、权益、法条、风险、管辖齐全。
- 未知值保留“待核实”，不自动补全。
- 法律条目附来源与核验状态。

**问题**

| 级别 | 问题 | 证据 / 影响 |
| --- | --- | --- |
| P0 | 移动端过长，关键结论和下一步埋在 7 屏以内看不到 | 6,491px；用户要先看完事实、关系、证据、权益才能知道“我现在最该做什么” |
| P0 | 与右侧事实档案重复展示“基本情况”全量字段 | 同一事实在两个位置维护视觉权重，分析页没有聚焦“解释” |
| P1 | 法律分析默认展开多条，主次不清 | 12 条依据、展开/收起，对低法律素养用户是认知负担 |
| P1 | 缺少“结论先行” | 没有三句话总结：可能主张什么、最大缺口是什么、先去哪里 |
| P2 | 缺少页内导航 | 长页只能滚动，无法快速到“证据/权益/依据/去哪里办” |

**方向**：分析页从“资料陈列”改为“解释页”：先给三条结论，再给证据缺口和渠道；法条默认折叠；基本事实回到唯一事实面板。

### 4.5 行动指南

**做得好**

- 有优先渠道、正式陈述、可勾选步骤、时效与风险、渠道汇总。
- 勾选状态持久化。
- 步骤含“需要准备”“可复制话术”“官方入口”。

**问题**

| 级别 | 问题 | 证据 / 影响 |
| --- | --- | --- |
| P0 | 8 个步骤全部展开，移动端 7,075px | 用户看不到“当前第几步”，也找不到“现在做什么” |
| P0 | 标题写“按顺序做”，但渠道实际可并行准备 | 文案过度规定动作，可能误导用户以为必须做完上一步才能联系部门 |
| P1 | 顶部“0/8 步”与案件头“11/11”同时出现，语义冲突 | 用户会以为案件已完成 |
| P1 | “标记完成”按钮过小，位于每步右上角 | 目标用户触摸成本高，完成动作不显眼 |
| P1 | 时效与风险被放在页面末尾 | 最需要先知道的期限信息，反而最后才看到 |
| P2 | 优先渠道、正式陈述、证据准备在分析和填报中重复 | 缺少“这一页只负责执行”的内容契约 |

**方向**：把 8 步重组为 3 个阶段（固定证据 → 核对金额 → 选渠道办理），默认只展开当前阶段/当前步骤；进度明确标注“办理进度”；期限贴在相关步骤旁；渠道可并行。

### 4.6 官方填报

**做得好**

- 7 步流程、字段状态、逐字段复制、正式陈述、证据目录、导出完整。
- “不自动登录/不代替提交”的边界反复出现。
- 字段来源事实可追溯。

**问题**

| 级别 | 问题 | 证据 / 影响 |
| --- | --- | --- |
| P0 | 移动端步骤条横向被截断，最后几步不可见且无滚动提示 | 390px 截图中只看到第 1–3 步，用户不知道还有 4–7 步 |
| P0 | 证据目录在移动端仍是 560px 宽表格，靠横向滚动看“获取方式” | 截图中最后一列被截断；低 literacy 用户不一定会横向滑 |
| P1 | “官方填报”这个标签容易被理解为“帮我提交” | 虽然正文有免责声明，但导航和 CTA 的第一印象有风险 |
| P1 | 26 个小于 12px 的文本节点 | 字段解释、状态、来源、提示都偏小；对工地场景和中年用户不友好 |
| P2 | 步骤条没有“当前进度/剩余步骤”的移动端总览 | 用户只知道当前是第 1 步，不知道全程多长 |

**方向**：导航改名为“填报参考”或“去官方提交（本人操作）”；移动端步骤用可读的步骤选择/分段条；证据目录改卡片；字段正文不小于 14px。

## 5. 跨页面问题

### 5.1 信息架构重复

| 信息 | 出现位置 | 问题 | 应有归属 |
| --- | --- | --- | --- |
| 案件基本事实 | 对话侧栏、分析“基本情况”、行动陈述、填报陈述 | 四处展示，权重相同 | 对话侧栏为唯一事实源；其他页面只引用摘要 |
| 正式陈述 | 行动、填报 | 两处全文/截断并存 | 填报为全文归属；行动只给入口 |
| 官方渠道 | 分析“去哪里办”、行动“推荐渠道”、填报第 1 步 | 三套说法 | 统一 `ChannelInfo` 组件与渠道数据 |
| 证据清单 | 分析、行动“需要准备”、填报“证据目录” | 三种颗粒度 | 分析讲缺口，行动讲现在带什么，填报讲逐项上传 |
| 进度 | 案件头 11/11、行动 0/8 | 两个数值无标签并列 | 信息完整度 / 办理进度分离 |

### 5.2 流程断点

当前流程是“对话 → 分析 → 行动 → 填报”，但界面没有持续告诉用户：

1. 我现在在哪一步？
2. 这一步的产出是什么？
3. 下一步只做哪一件事？
4. 我改过事实后，哪些结果过期了？

这比视觉更影响完成率。

### 5.3 法律与信任表达

- 不是缺少免责声明，而是声明与动作分离：用户点“官方入口”时，最需要看到“这是去官方平台，由你本人提交”。
- 不是缺少法条，而是法条太早、太多：先给“可能相关”，再让用户按需展开。
- 不是缺少 AI，而是 AI 身份不显眼：用户可能把模型回复误当正式法律意见。需要在回答附近持续标识“助手整理，不构成法律意见”。

| 重建 | 首页的视觉与信任区 | 吸收离线 HTML 的案卷气质，但不做营销长页 |

## 7. 优先级

### P0（不做就不算完成）

1. 行动指南改为“阶段 + 当前步骤”，移动端首屏能看到当前要做的一件事。
2. 分析和行动增加“结论先行 / 下一步”区，关键动作在两屏内可达。
3. 明确区分“信息完整度”和“办理进度”。
4. 移动端填报步骤可完整到达，证据目录不再依赖横向表格。
5. 填报相关文案明确“本人去官方平台提交”。

### P1（交付前必须）

1. 对话助手身份、引用折叠、回复长度约束。
2. 事实修改后的结果过期提示。
3. 统一事实/陈述/渠道组件，减少跨页重复。
4. 案件列表的“下一步”与空状态主次。
5. 官方入口与免责声明就近展示。

### P2（打磨）

1. 首页视觉身份与信任区。
2. 页内导航/折叠节奏。
3. 字号、触控目标、安全区。
4. 对话历史定位、回到最新。
5. 空/错/加载状态统一。

## 8. 基线结论

当前产品已经具备“能跑通”的骨架：匿名会话、真实 Agent、事实编辑、法律引用、分析、行动、填报、导出均存在；390px 无横向溢出；控制台无错误。问题不在功能缺失，而在：

- **任务焦点**：长页面把所有信息同时给用户，没有“现在只做这一步”。
- **进度语义**：信息完整度被误当成办理完成度。
- **移动优先**：桌面可读的内容直接堆到手机，形成 7–8 屏。
- **内容归属**：事实、陈述、渠道在多个页面重复，降低信任和效率。
- **产品气质**：正式前端比离线原型更冷、更薄，缺少案卷感与“有人陪你走”的安全感。

下一阶段的产品设计应围绕一句话展开：**让工友在两屏内知道“现在做什么”，并且相信这件事不会被产品代替或夸大。**
