# 迁移到 Qoder Sites 的说明（未执行）

> 本阶段只做本地开发预览。**没有部署到公网，也没有发布到 Qoder Sites。** 本文是迁移前的工程说明，不代表已完成上线。

## 1. 需要先决策的架构问题

本项目是“Next.js 前端 + Python FastAPI 后端 + SQLite”的全栈组合。Qoder Sites 适合托管 Web 前端；FastAPI 进程、SQLite 文件和本地内存导出不适合直接作为静态资源发布。

迁移前二选一：

### 方案 A：前端上 Sites，后端独立托管

- 前端部署为 Qoder Site；
- FastAPI 部署到支持 Python 常驻进程/容器的服务；
- 前端通过 HTTPS 调用后端，CORS 白名单限制站点域名；
- 优点：改动小，保留现有 Agent 与导出逻辑；
- 缺点：需要两个运行环境、两套监控和密钥管理。

### 方案 B：后端能力迁入 Next.js 服务端

- 将 FastAPI 路由改写为 Next.js Route Handlers / Server Actions；
- 数据库改为 PostgreSQL；
- DOCX/PDF 生成改为 Node 库或独立服务；
- 优点：单一站点；
- 缺点：重构量大，规则引擎、检索、导出都需要移植或重写。

**不建议**把 SQLite 文件直接放进站点静态目录，也不建议把 Python 进程塞进纯静态托管。

## 2. 前端迁移步骤（方案 A）

1. 确认 Qoder Sites 当前支持的 Next.js 版本、Node 版本与构建命令。
2. 在站点项目设置中配置：
   - `BACKEND_URL=https://<后端 HTTPS 域名>`
   - 不在前端配置任何模型密钥。
3. 检查 `next.config.mjs` 的 rewrite：
   - 若 Sites 支持服务端 rewrite，保持 `/api/py` 代理；
   - 若只支持静态资源，改为 `NEXT_PUBLIC_API_BASE=https://<后端>/api/v1`，并调整 `frontend/services/api.ts`。
4. 后端 `CORS_ORIGINS` 加入站点正式域名（含预览域名策略）。
5. 验证：
   - 创建案件、对话、分析、计划、表单、DOCX/PDF/TXT 导出；
   - 跨会话 404；
   - 移动端布局；
   - 浏览器控制台无错误。
6. 绑定域名、开启 HTTPS。

## 3. 后端迁移步骤

1. 容器化或使用支持 Python 的运行环境，启动：
   ```bash
   uvicorn backend.main:app --host 0.0.0.0 --port 8000
   ```
2. 将 `DATABASE_URL` 改为 PostgreSQL，例如：
   ```text
   postgresql+psycopg://user:password@host:5432/workerrights
   ```
3. 用 Alembic 或等价工具创建表；不要依赖 SQLite 自动建表。
4. 启动时执行种子导入，或改为一次性部署任务：
   ```bash
   python -m backend.database.init_db
   ```
5. 配置环境变量/Secrets：
   - `DATABASE_URL`
   - `CORS_ORIGINS`
   - `LLM_PROVIDER=mock`（未完成授权前不要切真实模型）
   - 如需模型：`LLM_API_KEY` 仅放服务端 Secret
6. 反向代理限制请求体大小、超时与速率；导出接口加限流。
7. 日志脱敏：不记录消息全文、电话、姓名、金额组合等敏感信息。
8. 备份：数据库定时备份；导出文件不落盘。

## 4. 数据与检索迁移

- 保留 `knowledge/*.json` 作为可审计数据源；
- 如启用 pgvector：
  - 增加 embedding 列与向量索引；
  - 保留关键词检索作为降级；
  - 记录嵌入模型版本；
- 每次发布记录知识库版本与核验日期；
- 不要在生产启动时无条件清空知识表；改为版本化种子/迁移。

## 5. 会话与账号

当前是匿名 `X-Session-Id`：

- 清除 localStorage 即失去案件；
- 无法跨设备找回；
- 适合演示，不适合正式服务。

上线前建议至少：

- 可恢复的匿名凭证（一次性恢复码）；或
- 手机号/微信等账号体系（需单独做隐私评估）；
- 会话过期与清理策略；
- 防枚举与限流。
