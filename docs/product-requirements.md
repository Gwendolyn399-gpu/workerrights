# 产品需求说明（v0.1 本机原型）

## 1. 背景与目标

河南建筑工地农民工遭遇欠薪时，常见困难不是“完全没有法律”，而是：

- 不知道该找劳动监察、仲裁、法院还是住建部门；
- 不会把零散经历整理成可受理的事实；
- 不知道哪些材料有用、怎么保存；
- 面对官方平台的长表单不知道每项怎么填；
- 容易被“包赢”“包追回”等承诺误导。

本产品把一次欠薪咨询拆成可核对的五步，帮助用户形成**事实清楚、证据有清单、渠道有依据、表单有草稿**的维权准备。产品做辅助，不代替律师、劳动监察或仲裁机构。

## 2. 目标用户

- 在河南建筑工地务工、被拖欠工资的农民工；
- 不熟悉法律术语，主要在手机上使用；
- 可能没有书面合同、没有考勤、只有微信聊天或工友证言；
- 需要先知道“下一步做什么”，而不是读完整部法律。

首期只覆盖：**河南省 · 建筑工地 · 工资拖欠**。其他场景在首页标注“即将支持”，不会假装可用。

## 3. 核心用户旅程

1. 首页了解产品边界，选择“开始说明情况”。
2. 对话中一次回答一个问题；可点快捷回复、语音输入、跳过或说“不知道”。
3. 系统实时整理右侧案件信息与进度；用户可随时点“修改案件信息”。
4. 信息足够后，系统复述应发/已付/欠发，用户确认。
5. 生成案件分析：关系图、证据、权利、法律依据、风险、管辖。
6. 生成行动指南：先固定证据、核对金额、书面确认、劳动监察、住建/根治欠薪平台、仲裁、法律援助、诉讼准备。
7. 填报助手按官方平台步骤整理字段；用户本人去官方页面复制、核对、提交。
8. 可导出 DOCX/PDF/TXT，作为线下咨询或投诉材料草稿。

## 4. 页面需求

### 4.1 首页

- 明确价值主张、适用地区和场景；
- 六个场景入口，仅“建筑工地欠薪”可用，其余明确“即将支持”；
- 展示五步流程、法律来源、隐私边界、免责声明；
- 提供“虚构演示案件”入口，不冒充真实案例。

### 4.2 对话式接待

- 一次只问一个最重要的问题，不展示复杂长表单；
- 快捷回复必须来自当前问题，不在确认后残留；
- 语音输入不可用时隐藏，不制造伪交互；
- 事实编辑器可修改地点、金额、合同、证据等；
- 显示进度、已确认字段、待核实字段；
- 侧栏可打开法律来源，标明核验状态；
- 用户说“不知道”时记录为待核实，不编造；
- 用户提到其他主题时，不把“不知道”错误归到当前问题。

### 4.3 案件分析

- 基本信息：地点、工种、时间、金额、主体；
- 横向用工关系图：建设单位 → 总包 → 分包/劳务 → 包工头 → 劳动者，未知节点明确标“待核实”；
- 证据四分类：已有、可补充、需要固定、暂缺；
- 权利主张：工资、未签合同可能涉及的二倍工资（需先核实关系）、赔偿金等，均用“可能/需核实”措辞；
- 法律依据卡片：条文、来源、时效、核验状态、官方链接；
- 风险提示：主体不清、证据不足、时效、金额不一致、复杂关系建议求助专业人士；
- 管辖建议：按项目所在地匹配，不假设每个区县都有独立机构；
- 导出入口。

### 4.4 行动指南

- 固定 8 个步骤，顺序体现“先证据、再核对、再沟通、再投诉/仲裁”；
- 每步包含目的、准备清单、渠道、法律依据、期限、风险；
- 步骤可勾选并持久化；
- 提供微信沟通草稿，只陈述事实，不威胁、不伪造；
- 提供正式事实陈述与证据目录；
- 事实变更后自动重建步骤，同时保留同名步骤的完成状态；
- 导出。

### 4.5 官方填报辅助

- 按“全国根治欠薪线索反映平台”的 7 个步骤展示 18 个字段；
- 每字段展示：值、状态（可填写/待补充/需核对/仅官方填写）、说明、复制按钮；
- 身份证号、银行卡号等不采集，标记“仅官方填写”；
- 明确提示字段结构待核验，实际以官方页面为准；
- 明确提示不自动登录、不自动提交；
- 提供正式陈述、简短描述、证据目录、复制摘要、导出。

## 5. 非功能需求

| 维度 | 要求 | 本版实现 |
| --- | --- | --- |
| 可运行 | 本机一条后端、一条前端命令启动 | 已实现 |
| 可追溯 | 法律结论必须能回到知识库条目 | 已实现 |
| 不编造 | 缺字段保持 `null/待核实`；无把握的推断不写入 | 规则约束 + 测试 |
| 会话隔离 | 不同匿名会话不能读取彼此案件 | `X-Session-Id` + 404 |
| 隐私 | 不采集身份证号；密钥仅服务端 | 已实现 |
| 导出 | DOCX/PDF/TXT 中文可读 | 已实现并实测 |
| 透明 | Mock 必须明确标注 | UI + API meta |
| 不做承诺 | 不保证胜诉/追回 | 文案 + 风险提示 |
| 不自动提交 | 只辅助填报 | 明确提示，无提交接口 |

## 6. 验收标准（本版）

- 从首页创建案件，只靠快捷回复可完成接待并确认；
- 确认后能打开分析、行动指南、填报助手；
- 三页都能导出 DOCX/PDF/TXT；
- 修改事实后分析/计划同步更新，跨会话不可见；
- 无浏览器控制台错误（Playwright 流程验证）；
- `pytest`、`npm test`、`npm run build` 全部通过。

## 7. 明确不做

- 不部署公网、不发布 Qoder Sites；
- 不接入真实政府平台、不自动提交；
- 不购买付费 API；
- 不把法律规则硬编码在 UI；
- 不把演示数据当真实案例；
- 不提供“包赢”结论或暴力讨薪建议；
- 不收集身份证号等非必要信息。
